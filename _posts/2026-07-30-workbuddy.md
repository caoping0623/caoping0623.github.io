## 一、WorkBuddy 是什么

### 1.1 一句话定义

**WorkBuddy** 是腾讯推出的**全场景职场 AI 智能体桌面工作台**。你用自然语言描述需求，它会像同事一样自主规划、执行多步骤任务，并交付**可验收的结果**（文档、表格、PPT、整理后的文件夹等），而不只是一段文字建议。

官网：[https://www.workbuddy.cn/](https://www.workbuddy.cn/)  
官方文档：[https://www.workbuddy.cn/docs/](https://www.workbuddy.cn/docs/)

### 1.2 它解决什么问题

传统 AI 对话的典型流程是：

> 你问 → 它答 → **你自己**去打开 Excel、改文件名、做 PPT、发邮件

WorkBuddy 想把中间那段「你自己动手」尽量拿走：

> 你说目标 → 它拆步骤 → 它读写本地文件 / 调连接器 → **直接交出产物**

这和本站前面讲的 Agent 路线一致：模型负责规划，工具负责动手，最终交付物才是验收标准。

### 1.3 和传统 AI 对话的区别

官方文档给出的对比如下：

| 维度 | 传统 AI 对话 | WorkBuddy |
| --- | --- | --- |
| 能力边界 | 只能对话、给建议 | 能实际执行任务 |
| 文件 | 需要你手动操作 | 可在授权范围内操作本地文件 |
| 任务复杂度 | 偏单步、短问答 | 支持多步骤复杂任务 |
| 输出形态 | 文字回复为主 | 交付可验收的结果 |

### 1.4 适合谁、适合干什么

官方按场景分成三类模式（日常办公是默认）：

| 模式 | 面向 | 典型任务 |
| --- | --- | --- |
| **日常办公** | 通用职场 | 报告、周报、会议纪要、数据分析、PPT、批量整理文件、深度调研 |
| **代码开发** | 工程师 | 代码生成/审查/修 Bug、理解陌生仓库、从需求到实现的辅助 |
| **设计创意** | 设计/产品 | 界面稿、组件方案、交互原型、Logo/海报、营销配图 |

一句话判断：如果你希望 AI **把事做完并留下文件**，而不是只给思路，WorkBuddy 就对口；如果你主要在 IDE 里写代码、改仓库，Cursor / CodeBuddy 之类写代码工具仍然更贴身——两者可以并存。

- **连接器（Connector）**：把外部服务接进来，技术形态包括 **MCP + CLI**、**Skill + CLI**

- **工作空间**：本次任务读写文件的边界——很像给 Agent 划定的「工位」

## 三、安装与登录

### 3.1 环境要求

据腾讯云 WorkBuddy Enterprise 安装文档（2026-07-20 更新）：

| 系统 | 要求 |
| --- | --- |
| **Windows** | Windows 10 及以上；不支持 Windows 7 / 8 / 8.1 |
| **macOS** | macOS 12（Monterey）及以上 |

另需：能访问外网（调用模型服务），以及已注册/可登录的 WorkBuddy 账号。

官网下载页还提供 **Mac x64 / Mac ARM64、Windows x64（兼容 ARM64）**，以及 iOS、Android、鸿蒙等移动端入口。桌面端是主战场；移动端/小程序更多用于查看结果、接收推送或远程发起（具体渠道以你客户端里实际支持的为准）。

### 3.2 下载

1. 打开官网 [https://www.workbuddy.cn/](https://www.workbuddy.cn/)
2. 点击下载；页面一般会自动匹配当前设备版本
3. 也可手动选择：Windows x64、Mac ARM64（Apple Silicon）、Mac x64（Intel）

### 3.3 安装

**Windows**

1. 双击安装包启动安装向导
2. 按提示完成安装
3. 启动 WorkBuddy

**macOS**

1. 双击 `.dmg`
2. 把 WorkBuddy 拖进 `Applications`
3. 从「应用程序」启动；若被系统拦截，到「系统设置 → 隐私与安全性」里允许打开

### 3.4 登录与权限

1. 打开应用，按引导登录（国内版常见为微信扫码等；国际站文档提到 Google / GitHub OAuth，以你实际看到的登录页为准）
2. 首次使用时会涉及**本地文件夹访问授权**

授权建议：

- **只授权任务真正需要的目录**（例如「文档/工作」「Downloads」），不要一上来全盘放开
- 敏感目录（证书、密码库、财务原件）先别给
- 每个任务还可以再指定更小的「工作空间」，把读写范围缩到当前任务

### 3.5 更新

打开 WorkBuddy → 左下角头像 → **检查更新**。有新版本时一般会自动下载并升级。

## 四、界面长什么样

主界面可以看成三块：

| 区域 | 作用 |
| --- | --- |
| **侧边栏** | 任务列表（可按文件夹分组），支持搜索与管理；底部是用户头像/设置入口 |
| **对话区** | 核心交互区：任务标题、消息流、输入框；看执行过程、继续追问都在这里 |
| **结果区** | 右侧面板：产物、全部文件、变更、预览等；可从任务标题栏展开/收起 |

记住一句话：**左边管任务，中间聊过程，右边看交付物。**

## 五、核心用法：创建并跑完一个任务

### 5.1 发起第一个任务

官方快速开始流程：

1. 打开 WorkBuddy，进入新建任务页
2. 在输入框用一句话写清需求，例如：
   - 「帮我把这份销售数据生成一个分析报告」
   - 「整理这个文件夹里的图片，按日期重命名」
   - 「根据这份需求文档生成一个 PPT」
3. （可选）选择 AI 模型
4. 点发送或回车，开始自主执行
5. 需要时再开新任务，**多个任务可并行**，在侧边栏切换查看

### 5.2 写好任务描述：比「会不会用」更重要

自然语言很好用，但**写清楚目标**会显著提高一次成功率。建议描述里至少覆盖四件事：

| 要素 | 问自己 | 示例 |
| --- | --- | --- |
| **目标** | 要做成什么 | 「生成带图表的销售分析报告」 |
| **输入** | 材料在哪 | 「用工作空间里的 `sales_q2.xlsx`」 |
| **输出** | 交付什么格式 | 「Word 报告 + 一张汇总表」 |
| **约束** | 风格/范围/禁忌 | 「面向管理层、控制在 5 页内、不要臆造数字」 |

官方示例句式可以直接抄：

- 「帮我把这份销售数据生成一个分析报告，包含图表」
- 「整理 Downloads 文件夹里的图片，按日期分类」
- 「根据这份会议纪要生成一个 PPT」
- 「分析这份简历，提取关键信息生成表格」
- 「调研一下近年 AI 行业趋势，写一份报告」

### 5.3 选择工作空间

创建任务时，点输入框左下角的 **选择工作空间**：

- 指定后，Agent 会在该目录范围内读写文件
- 不指定时，通常会在默认目录生成结果

**实践建议**：为不同类型的事建不同目录，例如：

```text
WorkBuddy/
├── weekly-report/     # 周报素材与产出
├── data-analysis/     # 表格与图表
├── ppt/               # 演示文稿相关
└── scratch/           # 临时试错
```

这样既好找产物，也避免 Agent 误碰别的项目文件。

### 5.4 补充上下文

| 方式 | 怎么做 |
| --- | --- |
| **@ 引用** | 用 `@` 引用文件、文档、规则等 |
| **粘贴截图** | `Ctrl/Cmd + V` 贴剪贴板图片 |
| **上传/拖拽** | 点上传或把文件拖进输入框 |
| **文字补充** | 在描述里写清目标、范围、约束、预期输出 |

### 5.5 任务跑起来之后看哪里

任务创建成功后：

1. 左侧列表出现该任务
2. 对话区持续显示执行过程与回复
3. 右侧结果区按任务类型展示**产物 / 全部文件 / 变更 / 预览**
4. 你可以继续追问（「图表改成柱状图」「摘要再压缩一页」），或并行开下一个任务

验收时优先看右侧产物，不要只看对话里的文字——**文件才是交付物**。

## 六、进阶能力：Skill、连接器、自动化

### 6.1 技能（Skill）：给 Agent 加「专项工具」

官方定义：Skill 为 WorkBuddy 增加「特定工具能力」——封装一组可执行脚本与工作流，使 AI 在授权下完成具体动作（读写文件、调第三方 API、查询信息等）。

这和本站讲的 [Skills]({{ '/2026/07/28/function-calling-mcp-skills/' | relative_url }}) 同属一类思路：**不是换模型，而是给模型一本可执行的操作手册/工具包。**

**怎么装**

在技能相关入口点「添加技能」，常见三种路径：

| 方式 | 说明 |
| --- | --- |
| **上传技能** | 导入本地技能包，拖拽或选择文件即可，导入后一般自动完成配置 |
| **查找技能** | 用任务描述让 WorkBuddy 帮你找相关技能 |
| **创建技能** | 用自然语言描述需求，让它生成相关技能 |

页面通常分成「技能市场（推荐、可一键装）」和「已安装（可在对话中调用）」。

**使用建议（官方也强调）**

- **只启用当前任务需要的 Skill**，减少误调用
- 第三方 Skill 先看权限、来源和脚本内容；优先官方推荐
- 涉及删除、批量写入、系统配置或资金类操作时，**先小范围试**，再放大
- 复杂 Skill + 复杂任务通常**积分消耗更高**

### 6.2 连接器（Connector）：接到腾讯办公生态和 MCP

连接器是 WorkBuddy 与外部服务之间的桥。技术形态包括：

- **MCP + CLI**（标准化协议）
- **Skill + CLI**（内置脚本）

官方文档写明当前已支持例如：**QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD、腾讯网盘** 等，并支持**自定义连接器**（可装自定义 MCP 服务）。管理页左侧导航进「连接器」；输入框里也有快捷管理入口。

**典型场景**

| 场景 | 例子 |
| --- | --- |
| 数据查询 | 搜乐享知识库、查 TAPD |
| 服务调用 | 发 QQ 邮件、建会议 |
| 文件管理 | 读写腾讯文档 / 网盘 |
| 消息通知 | 与办公 IM 协同（以实际已开通渠道为准） |

**以连接 QQ 邮箱为例（官方步骤摘要）**

1. 连接器页找到 QQ 邮箱，点 `+`
2. 用 QQ 邮箱 App 扫码授权
3. 确认权限（账号信息、读近一个月邮件、代发邮件等）
4. 浏览器弹窗点「打开」完成回跳——**关掉网页可能导致中断，需重配**
5. 卡片出现绿色圆点即表示已连接，可用开关启用/禁用

**权限边界（官方原则，很重要）**

- 每个连接器**独立授权**
- **不主动定时抓取**
- **不超出你在第三方服务里已有的权限**
- 代发邮件、改文档、建会议等写入操作，需你明确指令确认

自定义连接器：管理页右上角「自定义连接器」，按 MCP 方式接入；访问范围由你的配置决定，请先评估再启用。

### 6.3 自动化：到点自己干活

自动化把「人手点发送」换成「到点自动发起 Agent 任务」。配置保存在本地客户端（名称、prompt、调度规则、工作目录、状态等），触发时以**当前登录身份**执行。

**创建时主要填这些**

| 配置项 | 说明 |
| --- | --- |
| 名称 | 区分不同定时任务 |
| 工作空间 | 执行与保存目录；也可走自动分配的临时工作空间 |
| 提示词 | 任务目标与输出要求 |
| 模型与技能 | 指定用哪个模型、哪些 Skill |
| 定时规则 | 频率与生效日期区间 |
| 推送到小程序 | 开启后结果可同步到 WorkBuddy 小程序查看 |

不想从零写 prompt，可用官方**任务模板**（新闻推送、周报、学习计划等），再改成自己的版本。

**安全提醒（自动化比手动任务更危险）**

- 无人值守执行：涉及删除、批量改文件、对外发送的 prompt 要特别谨慎
- 先**低频试跑**，结果稳定后再提高频率
- 对文件改动、对外发送保留可追溯记录，便于核查
- 电脑需保持开机且客户端可用，定时任务才能触发（这是桌面 Agent 的物理限制）

## 七、几个可直接抄的使用姿势

### 7.1 周报：素材进工作空间，一句话生成

1. 建工作空间 `weekly-report/`
2. 把本周笔记、截图、导出的工单表丢进去
3. 发送：

```text
请根据工作空间里本周的材料，生成一份给主管看的周报。
结构：本周完成 / 进行中 / 风险与求助 / 下周计划。
输出 Word，语气简洁，不要编造材料里没有的数据。
```

4. 在右侧结果区打开 Word，不满意就追问修改

### 7.2 数据分析：表格 → 报告 + 图

1. 把 `sales.xlsx` 放进工作空间
2. 发送：「基于 sales.xlsx 做销售分析，输出带图表的报告，并单独给一张按区域汇总的表」
3. 验收数字是否和源表一致——**涉及数字务必人工抽查**

### 7.3 邮件整理：接 QQ 邮箱连接器

1. 按第六节连好 QQ 邮箱
2. 发送：「汇总近一周未读里和『预算』相关的邮件，按紧急程度排序，输出 Markdown 摘要；先不要代我回复」
3. 需要回复时再明确说「按摘要第 2 条草拟回复，等我确认后再发」

### 7.4 定时简报：自动化 + 小程序

1. 自动化里新建任务，提示词写清信息源与输出格式
2. 设每天固定时间
3. 打开「推送到小程序」，方便手机上看结果

## 八、使用建议与常见坑

### 8.1 提示词怎么写更稳

- **一次一事**：一个任务一个主目标，别在一句里塞「分析数据 + 做 PPT + 群发邮件」
- **先只读、再写入**：敏感操作分两步，先让它出方案/摘要，确认后再执行写入或发送
- **给验收标准**：「成功标准是生成 `report.docx`，且包含三张图」
- **并行任务要分工作空间**：避免两个任务抢同一批文件

### 8.2 积分与成本

WorkBuddy 按积分/套餐计量（官网有个人版档位说明，具体额度以账号页为准）。经验上：

- 短问答、简单提醒：消耗较低
- 长文档、代码巡检、多连接器分析、复杂 Skill：消耗更高
- **连接器自身的读写不一定单独计积分**，但对外部数据做理解、汇总时会消耗（以官方说明为准）

### 8.3 安全清单

| 做法 | 原因 |
| --- | --- |
| 最小权限授权文件夹 | 缩小误删/误改范围 |
| 第三方 Skill 先审再装 | 可能涉及本地文件、屏幕控制、数据外发 |
| 对外发送前二次确认 | 邮件/IM 以你的身份发出 |
| 自动化先试跑 | 无人值守放大错误 |
| 密钥不要塞进随意目录 | 工作空间内文件可能被任务读取 |

### 8.4 它不适合什么

- **替代严谨的人工决策**：合同终审、财务签字、线上变更仍需人负责
- **无网络离线硬刚**：依赖云端模型服务
- **替代专业 IDE 深度改大仓库**：代码场景能辅助，但重度开发仍建议 Cursor / 专业 IDE
- **「完全不用管」的黑盒外包**：Agent 会出错；复杂任务要会拆、会验、会追问

## 九、和本站其他文章怎么串起来

如果你已经读过前面几篇，可以这样建立坐标系：

| 概念 | 在 WorkBuddy 里对应什么 |
| --- | --- |
| **AI Agent** | WorkBuddy 客户端本身：接收目标、规划、执行、交付 |
| **Function Calling** | 模型决定调用哪些工具/步骤（产品层通常不可见） |
| **MCP** | 自定义连接器、部分官方连接器背后的协议形态 |
| **Skills** | 技能市场 / 本地技能包 / 自动创建的 Skill |
| **本地知识库** | 工作空间里的文件 + 乐享/文档类连接器 |

一句话：

### 10.2 核心要点

- WorkBuddy 的定位是**职场桌面 Agent**：目标是交付可验收成果，不是陪聊
- 用法骨架很简单：**工作空间 + 说清目标 + 看右侧产物 + 追问迭代**
- **Skill** 扩专项能力，**连接器/MCP** 接外部系统，**自动化** 把重复劳动变成到点执行
- 安全上坚持：**最小目录授权、敏感操作分步确认、第三方扩展先审后用**
- 官方入口：官网 [workbuddy.cn](https://www.workbuddy.cn/)，文档从[简介](https://www.workbuddy.cn/docs/)按「快速开始 → 创建任务 → 技能/连接器/自动化」读即可

### 10.3 最后

Agent 产品最近一年的分水岭，不再是「会不会回答」，而是「**能不能在你的电脑和办公系统里把活干完**」。WorkBuddy 把这条路做成了下载即用的桌面工作台，并把腾讯文档、邮箱、会议、乐享、TAPD 等生态接进同一条任务流。

对你最实用的用法不是一次装齐所有 Skill，而是：

> 先固定一个工作目录，用三五个真实办公任务把它跑熟；等交付物稳定了，再逐步加连接器和自动化。
