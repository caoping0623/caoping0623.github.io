## 0. 先建立一张「心智地图」

把车载网络想成一座城市：

| 生活类比 | 网络概念 | 车里常见形态 |
| --- | --- | --- |
| 马路 / 车道 | **物理链路**（线缆、PHY） | 100BASE-T1 / 1000BASE-T1 单对双绞线 |
| 门牌号（楼栋内） | **MAC 地址** | 每块网口一块 48-bit 硬件地址 |
| 小区门禁分区 | **VLAN** | 智驾 / 座舱 / 诊断 / 管理 互不「串门」 |
| 城市道路门牌 | **IP 地址** | ECU 的逻辑地址，跑 TCP/UDP |
| 快递公司业务 | **应用协议** | SOME/IP、DoIP、摄像头流、OTA 等 |
| 红绿灯与公交专用道 | **优先级 / TSN** | PCP、调度，保证关键帧准时到 |

**一句话**：以太网负责「把帧送到对的端口」；VLAN 负责「同一根物理网上划出逻辑隔离」；IP/应用层负责「业务怎么说话」。

## 1. 以太网是什么？（办公室版，三分钟）

### 1.1 最朴素的定义

**以太网（Ethernet）** 是一套把「数字比特」在设备之间传过去的局域网技术，核心标准族是 **IEEE 802.3**。

你家里路由器接电脑，用的就是以太网（或 Wi-Fi，那是另一套）。车上用的，是同一思想在 **汽车环境** 下的改装版：**车载以太网（Automotive Ethernet）**。

### 1.2 三个必须记住的词

1. **帧（Frame）**：链路上一次发送的「包裹」，里面装着目标 MAC、源 MAC、类型、数据、校验。
2. **MAC 地址**：网卡的「身份证」，全球唯一（或厂商烧录），交换机主要靠它转发。
3. **交换机（Switch）**：多端口设备，看见帧的目标 MAC，从对应端口送出去——**同一二层网内**不需要懂 IP。

### 1.3 交换机 vs 路由器（小白必分清）

| | 交换机（L2） | 路由器 / 三层交换机（L3） |
| --- | --- | --- |
| 看什么地址 | **MAC** | **IP** |
| 典型工作 | 同网段内转发 | 跨网段转发（不同 IP 子网之间） |
| 车内角色 | 中央以太网交换机、域控内 switch | 中央网关、部分带路由的 CGW/HPC |
| VLAN 关系 | 按 VLAN ID 隔离广播域 | 跨 VLAN 通信通常要 **路由**（或特殊策略） |

**口诀**：同 VLAN、同子网 → 交换机就能到；跨 VLAN → 一般要过网关/路由器。

## 2. 为什么汽车一定要上以太网？

### 2.1 CAN 不够用了

| 需求 | CAN / CAN FD | 车载以太网 |
| --- | --- | --- |
| 带宽 | 约 1–8 Mbps 量级 | 100 Mbps / 1 Gbps / 多千兆 |
| 智驾相机、激光雷达 | 很难扛 | 骨干网主力 |
| 大包刷写 / 日志 | 慢 | DoIP、文件传输友好 |
| 服务化软件（SOA） | 信号矩阵为主 | IP + SOME/IP 更自然 |
| 线束 | 多总线并行 | 可用星型/环型骨干减线束 |

CAN、LIN、FlexRay **不会消失**，它们仍适合局部执行器与低成本节点。今天的整车是：

> **以太网做骨干与高带宽域；CAN/LIN 做边缘与遗留；中间用网关做协议转换。**

### 2.2 和办公室以太网的关键差异

| 维度 | 办公室以太网 | 车载以太网 |
| --- | --- | --- |
| 线缆 | 常 4 对双绞线（Cat5e/6） | 多为 **单对双绞线 SPE**（减重、省空间） |
| 常见速率 | 1G / 10G | **100BASE-T1、1000BASE-T1**，边缘还有 10BASE-T1S |
| 接头 | RJ45 | 车规连接器（密封、振动） |
| 拓扑 | 星型为主 | 星型 + 分区交换机 + 可选环网冗余 |
| EMC / 温度 | 办公环境 | 严酷车规（ISO 等 EMC/环境要求） |
| 休眠唤醒 | 较少关心 | **TC10** 等链路休眠/唤醒很重要 |
| 确定性 | Best-effort 够用 | 常要 **AVB/TSN**、VLAN 隔离 |

「车载以太网」不是换个接头那么简单，而是 **PHY + 交换芯片 + 协议栈 + 休眠策略 + 功能安全/网络安全** 一整套。

## 3. 物理层：车上那根「单对线」在干什么？

### 3.1 BASE-T1 家族（先认脸）

| 名称 | 大致带宽 | 典型用途 |
| --- | --- | --- |
| **10BASE-T1S** | 10 Mbps | 分区边缘、多点总线型低成本节点 |
| **100BASE-T1** | 100 Mbps | 大量量产骨干/域间链路 |
| **1000BASE-T1** | 1 Gbps | 智驾、座舱高带宽、中央骨干 |
| 多千兆 / 光 | 2.5G+ | 高端中央计算、传感器聚合 |

**T1** 表示 **单对（Single Pair）**。同一对线上要做全双工通信，靠 PHY 芯片里的回波抵消等技术——对你写应用的人：插对线、配好 PHY 模式即可，细节交给硬件与驱动。

### 3.2 PHY、MAC、交换机芯片怎么串起来

- **MAC**：负责帧格式、MAC 地址。
- **PHY**：负责在铜线上发出/收到模拟信号。
- **Switch**：根据 MAC（和 VLAN）决定从哪个端口出去。

很多域控/中央网关是：**一片多口车规交换机 + 若干 PHY + 主 CPU 的 CPU 口（CPU port）**。

### 3.3 链路状态：Link Up 才能谈业务

排查第一步永远是：**物理链路通不通？**

- Link LED / 寄存器显示 Link Up
- 自协商是否匹配（速率、主从 Master/Slave——T1 常有主从配置）
- 线序、接插件、短路、EMC 干扰导致间歇掉链

**没有 Link，上面的 VLAN、IP、SOME/IP 全是空谈。**

## 4. 以太网帧长什么样？（为 VLAN 做铺垫）

### 4.1 经典以太网帧（无 VLAN）

大致结构（示意）：

```text
| 前导码 | 目标MAC(6) | 源MAC(6) | EtherType(2) | 数据载荷 | FCS校验(4) |
```

- **目标 MAC**：发给谁（单播 / 组播 / 广播 `FF:FF:FF:FF:FF:FF`）
- **源 MAC**：谁发的
- **EtherType**：里面装的是什么，例如 `0x0800`=IPv4，`0x86DD`=IPv6，`0x0806`=ARP
- **FCS**：循环冗余校验，坏帧丢弃

### 4.2 带 VLAN 的帧（802.1Q）——整车最重要的一张图

插入 **4 字节 VLAN Tag** 之后：

```text
| 目标MAC | 源MAC | 802.1Q Tag(4) | EtherType | 数据 | FCS |
              ↑
         TPID + TCI
```

**Tag 内部**：

| 字段 | 位数 | 含义 |
| --- | --- | --- |
| **TPID** | 16 | 通常 `0x8100`，表示「后面是 VLAN 标签」 |
| **PCP** | 3 | **优先级**（Priority Code Point），0–7 |
| **DEI** | 1 | 拥塞时可丢弃标记（Drop Eligible） |
| **VID** | 12 | **VLAN ID**，0–4094（0 与 4095 有特殊含义） |

**记住三件事**：

1. VLAN 是 **二层标签**，在 MAC 头后面，在 IP 头前面。
2. **VID** 决定「你属于哪个逻辑局域网」。
3. **PCP** 决定「交换机调度时你有多优先」（和 TSN/QoS 配合）。

## 5. VLAN 讲透：小白也能画整车隔离图

### 5.1 VLAN 到底解决什么问题？

一句话：**同一套物理交换机和线缆上，划出多个互不干扰的逻辑网络。**

没有 VLAN 时：所有 ECU 在一个大二层网里，广播风暴、误配 IP、座舱娱乐包冲撞智驾控制包的风险都更大。

有了 VLAN：

- 智驾相机流在 **VLAN 20**
- 座舱多媒体在 **VLAN 30**
- 诊断 DoIP 在 **VLAN 40**
- 网络管理 / gPTP 在 **VLAN 100**

物理上可能都接到同一台中央交换机，**逻辑上却像几张独立的局域网**。

### 5.2 广播域：为什么隔离这么重要

同一 VLAN 内：

- ARP「谁是 192.168.10.5？」会 **广播** 到该 VLAN 所有端口
- 未知单播也可能泛洪

跨 VLAN：

- 默认 **二层不转发**（交换机按 VLAN 隔离）
- 要通信 → 交给 **三层路由 / 网关防火墙**（可精细做 ACL）

这对汽车网络安全极关键：诊断仪不该随便摸到智驾传感器原始流；座舱 App 不该二层直达底盘安全相关域（具体以主机厂安全架构为准）。

### 5.3 Access 口 vs Trunk 口（工程里天天用）

| 端口类型 | 帧上有没有 VLAN Tag | 典型接法 |
| --- | --- | --- |
| **Access（接入）** | 进出该口时，对终端往往是 **无 Tag**；交换机在入口打上默认 VID | 接「只会说普通以太网」的 ECU |
| **Trunk（中继）** | 携带 **一个或多个 VID 的 Tag**，多 VLAN 复用一根线 | 交换机 ↔ 交换机，或交换机 ↔ 懂 VLAN 的域控 |

生活类比：

- **Access**：小区单元门，出门就进「本单元」（一个 VLAN）
- **Trunk**：主干道，车上贴着「去往哪个小区」的标签（多个 VLAN）

**常见翻车点**：

1. ECU 配成发 Tag，口却配成 Access 期望无 Tag → **全丢包**
2. Trunk 允许的 VID 列表漏配 → **某个 VLAN 通、另一个不通**
3. 两端 Native VLAN / PVID 不一致 → **诡异互通或环路风险**

### 5.4 PVID、允许列表、Tagged/Untagged

配置交换机时你常会看到：

| 概念 | 含义 |
| --- | --- |
| **PVID**（Port VLAN ID） | 该端口「默认归属」的 VLAN；无 Tag 进来时打上这个 VID |
| **Allowed VLANs** | Trunk 口允许通过哪些 VID |
| **Tagged** | 该 VLAN 在该口以带 Tag 形式进出 |
| **Untagged** | 该 VLAN 在该口以不带 Tag 形式进出（常用于 Access） |

### 5.5 PCP 优先级：VLAN 不只是隔离，还参与排队

PCP（0–7）让交换机知道：**拥塞时先送谁**。

示例（示意，量产以主机厂 QoS 矩阵为准）：

| PCP | 典型业务 |
| --- | --- |
| 7 | 网络控制、关键管理 |
| 5–6 | 控制类、高优先级诊断/安全相关 |
| 3–4 | 音视频 / AVB 流 |
| 0–2 | 尽力而为：后台下载、非实时日志 |

**注意**：只打高 PCP 不够；车规确定性往往还要 **TSN 调度（如 802.1Qbv）**、带宽预留（Qav）等。PCP 是「优先级语言」，TSN 是「时刻表」。

### 5.6 整车 VLAN 规划怎么做？（可直接当模板）

下面是一份 **教学用示例规划**（VID 数字请按贵司规范替换，切勿照搬量产）：

| VLAN ID | 名称 | 典型成员 | 备注 |
| --- | --- | --- | --- |
| 10 | BODY | 车身域控、分区 I/O | 可与 CAN 网关旁路 |
| 20 | ADAS | ADCU、相机 ECU、部分雷达网关 | 高带宽、严隔离 |
| 30 | COCKPIT | 座舱 SoC、仪表、HUD 相关 | 与 ADAS 二层隔离 |
| 40 | DIAG | DoIP Edge、OBD 以太网口、诊断路由 | 常单独划，便于防火墙 |
| 50 | FOTA | OTA Master、大包传输路径 | 可与 DIAG 合并或细分 |
| 100 | MGMT | gPTP、部分网络管理、交换机管理 | 高优先级 |

设计原则：

1. **按安全域与带宽域划分**，不要按「哪个供应商」随便划。
2. **诊断 VLAN 独立**，配合 DoIP Routing Activation 与防火墙。
3. **跨 VLAN 只走规定网关**，并写清 ACL（谁允许访问谁的哪类端口）。
4. **时间同步（gPTP）** 与业务 VLAN 的关系要在规范里写死（同 VLAN 或专用 MGMT）。
5. 文档化：**每端口 PVID、Tag/Untag、允许 VID、IP 子网、默认网关**——这是网络交付物，不是可选项。

### 5.7 VLAN 与 IP 子网的关系

最佳实践（强烈建议）：

> **一个 VLAN ↔ 一个 IP 子网**（或明确的一对一映射）。

例如：

- VLAN 20 → `10.20.0.0/24`
- VLAN 30 → `10.30.0.0/24`
- VLAN 40 → `10.40.0.0/24`

跨 VLAN 通信：源主机把包交给 **默认网关**（常是中央网关），网关改写二层头后从另一个 VLAN 出去。

**反例**：多个无关业务塞进同一 VLAN 同一大子网——广播域过大，安全边界模糊，排障极痛。

### 5.8 静态 VLAN vs 动态（车内现实）

车内几乎全是 **静态 VLAN**：端口与 VID 在下线配置/刷写时写死。

办公室常见的 802.1X 动态 VLAN，车内偶见于特殊运维口，**不是量产主路径**。对你而言：把 **VLAN 矩阵表** 配对比折腾动态分配重要得多。

### 5.9 Q-in-Q（双层 Tag）要不要关心？

**Q-in-Q**：外层再套一层 VLAN（运营商常用）。整车内部多数方案 **用不到**；若涉及跨车云隧道、特殊产线夹具网络，才可能碰到。小白阶段先精通单层 802.1Q 即可。

## 6. 从二层到三层：车上的 IP 怎么配？

### 6.1 为什么还要 IP？

交换机用 MAC 就能在 VLAN 内转发，但：

- 应用（SOME/IP、DoIP、HTTP）习惯 **Socket：IP + 端口**
- 跨 VLAN、跨子网必须走 IP 路由
- 诊断仪按 **逻辑地址 / IP** 找 ECU（DoIP）

所以车载以太网几乎总是：**以太网 + VLAN + IPv4（主流）+ UDP/TCP**。

### 6.2 地址分配常见做法

| 方式 | 说明 |
| --- | --- |
| **静态 IP** | 量产最常见；与 ECU 诊断逻辑地址映射表绑定 |
| DHCP | 多用于产线、研发台架、部分座舱场景 |
| 链路本地 | 特殊发现场景，非整车主方案 |

务必维护一张表：

`ECU 名 | 接口 | MAC | VLAN | IP | 掩码 | 网关 | DoIP 逻辑地址`

这张表是整车网络与诊断的「宪法」。

### 6.3 ARP：IP 到 MAC 的翻译

同 VLAN 内第一次通信常靠 **ARP**：「IP=x.x.x.x 的 MAC 是谁？」  
ARP 失败 → ping 不通的常见根因之一（VLAN 错、口错、防火墙丢广播）。

- **骨干**：以太网星型（或环型冗余）
- **边缘**：分区控制器下挂 CAN/LIN，缩短线束
- **诊断**：外部经 DoIP 进 DIAG VLAN，再由网关路由到目标（见诊断路由文）
- **隔离**：业务 VLAN 分离；跨域必须经 CGW 策略

### 7.2 域控时代 vs 分区时代（网络视角）

| | 域控为主 | 分区 + 中央计算 |
| --- | --- | --- |
| 交换机位置 | 中央 + 各域控内嵌 | 中央 + 各 Zone Switch |
| VLAN 粒度 | 按功能域 | 按区域 + 功能叠加，规划更复杂 |
| 线束 | 域内仍可能较长 | 区域汇聚，骨干更清晰 |
| 故障域 | 单域控故障影响一域 | 分区故障影响一区 I/O |

### 7.3 环网冗余（了解即可）

高端方案可能用 **以太网环**：一路断了，另一路仍通。常配合 TSN/冗余协议。量产是否采用取决于成本与功能安全目标；不是所有车都有环。

## 8. 跑在以太网上的「车载业务协议」

物理与 VLAN 通了之后，上层常见：

| 协议 | 作用 | 和 VLAN 的关系 |
| --- | --- | --- |
| **SOME/IP** | 面向服务的中间件（RPC、事件、服务发现） | 跑在某业务 VLAN 的 IP 上 |
| **DoIP** | 诊断 overlay IP（ISO 13400） | 常独占或紧绑 DIAG VLAN |
| **AVB / IEEE 1722** | 音视频桥接流 | 常要时间同步 + 专用流 VLAN/优先级 |
| **TSN** | 确定性以太网能力集（时间、调度、整形、冗余等） | 与 PCP、队列、门控列表强相关 |
| **gPTP (802.1AS)** | 全网时间同步 | 常走 MGMT 或约定 VLAN |
| **MACsec** | 二层加密可选能力 | 安全架构的一环 |

层次记忆：

```text
SOME/IP / DoIP / 相机应用
        ↓
   UDP / TCP
        ↓
      IP
        ↓
 以太网帧 + VLAN (+ TSN)
        ↓
   100/1000BASE-T1
```

## 9. TSN / AVB：为什么「有带宽还不够」？

办公室下载电影：晚 50ms 无感。  
车上控制或同步音频：晚 50ms 可能不可接受。

**TSN（Time-Sensitive Networking）** 在以太网上增加「可预期」能力，常见成员包括：

| 标准 | 作用（直觉） |
| --- | --- |
| **802.1AS (gPTP)** | 大家手表对齐 |
| **802.1Qbv** | 按时间表开门送指定队列 |
| **802.1Qav** | 信用整形，防止占满带宽 |
| **802.1Qbu** | 帧抢占，让紧急帧插队 |
| **802.1CB** | 多路径复制去重，提高可靠性 |

小白结论：

- **VLAN + PCP**：先隔离、再粗分优先级  
- **TSN**：要「准时」时再上  
- 不是所有 VLAN 都要上满套 TSN；按流的关键等级选型

## 10. 交换机在车里具体做什么？（配置清单思维）

一台车规交换机的典型配置项：

1. 每端口：**速率、主从、使能**
2. 每端口：**PVID、Tag/Untag、Allowed VLAN**
3. **VLAN 表** 与端口成员
4. **MAC 学习表** / 老化时间
5. **QoS**：PCP → 队列映射、限速
6. （可选）TSN：门控列表、流过滤
7. 镜像口（抓包）、风暴抑制、ACL
8. 休眠唤醒（与 TC10 等协同）

软件侧（AUTOSAR 常见概念，名字以栈为准）：

- Eth / EthIf / EthSM：接口与状态管理  
- TcpIp / SoAd：套接字适配  
- 与 VLAN 相关的控制器 / 收发队列绑定

## 11. 端到端通信走读（把知识串起来）

**场景**：座舱 SoC（VLAN 30, IP 10.30.0.10）调用车身服务（VLAN 10, IP 10.10.0.20），经中央网关。

1. 座舱应用发 UDP 到 `10.10.0.20:xxxxx`（SOME/IP）
2. 发现目标不在本网段 → 交给 **默认网关** MAC
3. 座舱口是 Access VLAN 30：帧出 ECU 时可能无 Tag，进交换机被标成 VID=30
4. 交换机把帧送到 **网关的 VLAN30 口**
5. 网关解包，查路由/防火墙：允许后，从 **VLAN10 口** 改写二层头发出
6. 交换机按 VID=10 送到车身域控
7. 车身协议栈交给 SOME/IP 服务处理

**若两端误配在同一 VLAN**：可能「碰巧 ping 通」但违反安全架构——**通 ≠ 正确**。

**诊断场景**：外部测试仪 → DIAG VLAN → DoIP Edge → 路由到目标 ECU 所在 VLAN/CAN。细节见[诊断路由文]({{ '/2026/07/30/vehicle-diagnostic-routing/' | relative_url }})。

## 12. 抓包与排障：以太网小白实战顺序

按这个顺序查，效率最高：

| 步骤 | 检查项 | 不通时的典型现象 |
| --- | --- | --- |
| 1 | 物理 Link | 完全无包 |
| 2 | 端口使能 / 主从 | 间歇 Up/Down |
| 3 | VLAN / PVID / Trunk 允许列表 | ARP 全无、对端收不到 |
| 4 | IP / 掩码 / 网关 | 同网段通、跨网段不通 |
| 5 | ARP / 防火墙 / ACL | ping 不通或单向通 |
| 6 | UDP/TCP 端口与应用 | ping 通但业务失败 |
| 7 | QoS/TSN 丢高优先级？ | 偶发超时、音视频卡顿 |

**抓包建议**：

- 在交换机 **镜像口** 抓，比盲猜有效
- 看帧里有没有 `0x8100` VLAN Tag、VID 对不对
- 看 PCP 是否符合 QoS 矩阵
- DoIP 看 TCP 13400、路由激活是否成功

## 13. 和 CAN 网络如何共存？

| 点 | 说明 |
| --- | --- |
| 网关 | 中央/分区网关做 **以太网 ↔ CAN** 信号或 PDU 路由 |
| 诊断 | DoIP 进以太网后，可转为 DoCAN（ISO-TP）到传统 ECU |
| 不要幻想 | 不是所有 CAN 节点都会「变成」以太网节点；成本与实时性决定边界 |
| 信号设计 | 以太网侧重服务/大包；CAN 侧重周期信号——架构师要定义边界，而不是简单「全迁」 |

## 14. 安全：VLAN 不是银弹

VLAN 提供的是 **逻辑隔离与广播域控制**，不是密码学安全。

完整车载以太网安全通常还要：

- 防火墙 / ACL（跨 VLAN 白名单）
- 诊断鉴权、SecOC、证书体系（视主机厂）
- 可选 **MACsec**、TLS（会话层）
- 符合 UNECE R155 等网络安全流程的威胁分析

**错误认知**：「分了 VLAN 就安全了。」  
**正确认知**：「VLAN 是分区墙；墙上还要装门禁与监控。」

## 16. 一页纸复习

- **以太网** = 用帧在链路上搬数据；车载常用 **单对 T1 PHY**。  
- **交换机** 看 MAC（+VLAN）转发；**路由器/网关** 看 IP 跨子网。  
- **VLAN（802.1Q）** = 4 字节标签里的 **VID + PCP**；物理一张网，逻辑多张网。  
- **Access** 对终端多无 Tag；**Trunk** 多 VLAN 带 Tag 复用。  
- **一 VLAN 一子网**；跨 VLAN 走网关 + ACL。  
- 上层：**SOME/IP / DoIP / 媒体流**；要准时再上 **TSN**。  
- 排障顺序：**Link → VLAN → IP → 应用**。

## 17. 结语

车载以太网难，难在它不是「会 ping 通」就够，而是 **带宽、隔离、安全、确定性、休眠、与 CAN 共存** 一起做对。

对小白最划算的投资是：真正弄懂 **VLAN 标签在帧里的位置**、**Access/Trunk 行为**、以及 **整车 VLAN/IP 矩阵表**。这三样通了，再看域控、DoIP、TSN，会清晰一个数量级。
